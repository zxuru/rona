**Nota:** la causa del destrozo de T412 quedó medida. En Windows un directorio que es el `cwd` de
un proceso vivo no se puede renombrar, y `git worktree remove` responde **borrando todo el
contenido** y fallando al quitar la raíz (255): el checkout se queda sin archivos versionados ni
`node_modules`, que es exactamente lo que se vio. Ahora `cerrar` y `abandonar` lo detectan antes de
tocar nada (renombrar y deshacer) y se niegan. Además, después de `git worktree remove` se reintenta
el borrado de lo que git deja atrás (medido con `.worktrees/T414`, que quedó con `.tmp/`,
`node_modules/` y `packages/`) y, si algo se resiste, se dice con el comando que lo retira.

Lo que no tiene prueba que lo discrimine: el reintento de `retirarRestos` en sí, porque el residuo
de git es intermitente y el caso real ya no se reproduce a voluntad. Queda cubierto por la prueba de
`enUso`, que es la condición que lo provoca. Sigue abierto podar `.tmp/` (tarjeta en *Pendiente*).
